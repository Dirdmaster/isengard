Zell-ish terminal layouts

Same dashboard, three different ways to integrate terminal panes that keep the "everything visible at once" Zellij feel. Click whichever direction you want me to mock in Pencil.

A. Side-pane terminal column (always visible)

Terminals live as horizontal splits in a fixed column on the right of the inspector. Always present (no expand/collapse), always tile-based. Drag dividers to resize. Add a new terminal = new horizontal split. Closest analog: a Zellij workspace docked to the right side of the dashboard.

Pros

  • Always-visible terminals — no toggle/expand mental overhead
  • Tiles naturally; multiple terminals visible at once (zell-ish)
  • Bottom keybar matches Zellij muscle memory
  • Inspector + terminal coexist, both first-class

Cons

  • Right-column real estate split 3 ways (timeline / inspector / terminals)
  • Less screen for events on smaller displays

B. Tiling bottom drawer (multi-pane, no tabs)

Same bottom position as VS Code style, but instead of tabs hiding sessions behind each other, all sessions are visible side-by-side as tiled panes. Drag dividers between them to resize. Add a new session = new tile. Bottom keybar with current mode + bindings.

PANE ⌘\split right ⌘-split down ⌘wclose pane ⌘↓collapse drawer live · 247

Pros

  • Bottom-anchored — doesn't fight inspector real estate
  • Multi-pane = zell-ish "tile your shells"
  • Drawer collapses cleanly when not in use
  • Familiar drawer position from VS Code/Datadog/Grafana

Cons

  • Many tiles in a thin horizontal strip = cramped reading
  • Each pane gets ~250-300px wide which is tight for logs

C. Floating panes (Zellij floating mode)

Press a key (e.g. Ctrl+\`) → terminals float over the dashboard, draggable + resizable. Multiple floating panes can stack. Doesn't reshape any underlying layout. Closest to Zellij's Ctrl+f floating-pane mode.

Pros

  • Doesn't shift dashboard layout — pure overlay
  • Familiar Zellij floating-mode behavior
  • Can summon/dismiss with one key

Cons

  • Floating UIs feel hacky for serious workflows
  • Z-ordering / where-do-they-go problems on small screens
  • Less scalable to 4+ open terminals
My take: A (side-pane terminal column) is the most zell-ish answer for this product. Always-visible, naturally tiled, the bottom keybar carries the mode/bindings convention. The right-column real estate trade-off is real but justifiable for a developer tool — the inspector becomes narrower, the terminals get a permanent home. It treats terminals as a first-class neighbor of the dashboard, not a hideable accessory.

B is the safer compromise (familiar drawer position, multi-pane). C looks cool but the floating-window pattern doesn't scale past 2 open shells without becoming a window-management problem. Pick what feels right.
