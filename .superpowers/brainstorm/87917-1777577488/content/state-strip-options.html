State strip — pick the organization

The chip-per-container layout breaks at scale. Three patterns that scale + give clean visual separation from the timeline. All shown in dashboard context (state strip on top, first row of timeline below) so you can judge proportion.

A. Aggregate + exceptions (recommended)

A small mini-grid of all containers up top (each cell = one container, color-coded) + only the rows that need attention listed below. Healthy containers DON'T appear individually. Scales to 50+ hosts because the only-issues list stays the same length on a healthy day (zero rows). Card has its own background + margin for clear separation.

Pros

  • Scales to any fleet size — issues list stays bounded
  • Healthy days look CALM (zero issue rows)
  • Mini-grid gives instant visual ratio
  • Strong card separation from timeline

Cons

  • Healthy containers aren't individually visible (drill in via grid hover or ⌘K)
  • Card background is a real visual weight at the top of the screen

B. Mini-bars per host (compact rows)

One row per host. Each container is a small color-coded segment (max-width capped so 50 containers still fit). Compact enough that 20 hosts fit comfortably in the same vertical space the chip layout used for 3.

Pros

  • One row per host — predictable rhythm
  • Container ratios visible per host
  • Scales to ~20 hosts before scrolling

Cons

  • Container names not visible (only counts)
  • 50+ hosts = scrollable strip = competes with timeline scroll
  • Less "alarm" weight when something is broken (issue is buried in a row)

C. Single rollup banner (most compact)

The minimum. Single line: aggregate counts + a mini-grid + an "Expand" affordance. When healthy it's a quiet green check + "All systems healthy". When something breaks, the icon turns amber/red. Per-host detail via expand or via the Hosts tab.

Pros

  • Scales infinitely — single line regardless of fleet size
  • Maximum timeline real estate
  • Very calm when healthy ("All systems healthy" + green check)

Cons

  • Detail requires expand or another tab — hidden by default
  • Less "at a glance" info — you trust the aggregates
My take: A (aggregate + exceptions) is the strongest. It scales perfectly (issue list is bounded by # of issues, not # of containers), has obvious card separation, and answers both "how big is the problem?" (aggregate counts + grid) and "what specifically?" (named issue rows). On a healthy day the issue rows just disappear and the strip becomes very calm.

C is what I'd pick if you want maximum timeline space. B works for ≤20 hosts but breaks the same way the chip layout did just at a higher ceiling.
